# M-Caddie — 已确定决策与待确认事项

## A. 已确定的决策（AI 不应重新发明）
1. 产品名为 **M-Caddie**。
2. 首先开发个人 MVP，未来才考虑商业化。
3. 目标设备为 iPhone 14 Pro Max 与 Apple Watch SE 3。
4. 采用原生 Swift + SwiftUI，而不是 React Native。
5. Watch-first：球场内尽量通过 Watch 完成关键流程。
6. 决策引擎独立为纯 Swift `MCaddieCore` Package。
7. Watch 端本地优先保存；不能要求 iPhone 或网络始终在线。
8. 击球后的初始口述报告要经过确认。
9. 走到球位后更新同一条 Shot，追加实际位置/球位信息，不创建重复击球。
10. 估计值与后续观测值必须分开保存，保留时间、来源与精度信息。
11. GPS 代表设备位置的观测，不保证等于球的准确位置。
12. 数值型球杆/策略建议必须可测试、可解释；LLM 不可成为唯一数值决策器。
13. 先做最小可构建项目，再逐步实现 GPS、语音、持久化、同步和决策。
14. 不假设 18Birdies 等第三方 API 可用；未来用适配器对接已确认的数据来源。

## B. 初始个人球杆数据（不是最终校准值）
- Driver：约 200 yd total；挥速 75–80 mph；常见右曲。
- 3-wood：约 160–180 yd total；挥速 70–75 mph；常见右曲。
- Driver：TaylorMade Burner 10.5°，Matrix Speed Rul-Z 50 R Flex。
这些是初始近似 total，不是 carry。其余球杆距离未提供。

## C. 实施前需要确认/验证的技术事项
1. 当前 Xcode 版本与可用 iOS/watchOS SDK。
2. 最低 iOS/watchOS deployment target。
3. Xcode 创建 iOS + Watch App 的具体模板和 target 结构。
4. SwiftData 在选定 watchOS 目标上的支持、限制与迁移策略；若不合适再比较 SQLite/Core Data。
5. Watch 端语音识别和语音合成的可用 API、支持语言、离线行为和权限要求。
6. 户外环境中语音识别准确率及风噪降级方案。
7. 回合期间定位、应用切换/屏幕关闭时的实际行为，以及电池消耗。
8. 是否使用 workout session 辅助回合持续体验；须验证平台限制，不能假设获得无限后台执行。
9. WatchConnectivity 的消息/文件/应用上下文策略和冲突解决规则。
10. 球场数据提供方、球场几何、果岭位置的来源与许可。
11. 内部距离单位及 UI 显示单位；当前 UI 倾向 yards，但需统一实现。
12. 球杆距离的输入/校准流程（手动初始值、实际击球统计、carry/total 分别记录）。
13. 风险偏好、目标策略和建议的默认保守程度。
14. 语音解析采用纯本地规则、Apple 系统能力、远端模型或混合方案；任何远端处理须单独评估隐私、成本与网络依赖。
15. 是否需要云端账户/备份；首版默认不依赖。
16. Bundle ID、App Store 名称可用性、开发者签名和发布计划。
17. 是否需要导出/导入格式及备份策略。

## D. 设计原则：遇到未决事项时
- 先列出选项、优缺点和对 MVP 的影响。
- 优先选择风险最低、易测试、易替换的方案。
- 不要在没有确认的情况下增加后端、订阅、外部 AI API 或第三方追踪服务。
- 如果 API 行为与文档冲突，以当前 SDK 编译结果和官方文档为准，并记录验证证据。
