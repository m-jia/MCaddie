# M-Caddie — 分阶段路线图

各阶段按验收结果推进，不把时间估算当成承诺。实际工期取决于 Swift 学习、Xcode 环境和 watchOS API 验证。

## Phase 0 — 环境与最小骨架
目标：
- 安装并启动稳定版 Xcode。
- 创建 SwiftUI iOS App 和配对的 Watch App。
- 在 iPhone 14 Pro Max 与 Apple Watch SE 3（或对应模拟器）上构建运行。
- 创建 `MCaddieCore` Swift Package。
- 添加一项最简单的 Core 单元测试。
验收：
- 项目可构建；iPhone 和 Watch 各有一个可见的最小页面。
- Git 初始提交完成。
- 记录 Xcode 版本、部署目标、设备运行结果。

## Phase 1 — 纯本地击球工作流
目标：
- 建立 Round、Shot、ShotObservation 等领域模型。
- 先用按钮/结构化输入实现“报告 → 预览 → 确认 → 本地保存”。
- 到球位后更新同一 Shot ID。
- 使用假数据/模拟定位完成端到端测试。
验收：
- 口述报告尚未实现也不妨碍流程测试。
- 同一杆后续更新不会生成重复 Shot。
- 应用重启后已确认记录仍在。
- 关键状态转移和持久化逻辑有测试。

## Phase 2 — Watch 定位
目标：
- 接入 Core Location 或当前 SDK 中适用的原生定位方式。
- 显示定位状态与精度。
- 保存球位位置观察，而不是把设备坐标误称为球的精确坐标。
验收：
- 允许/拒绝权限路径均可运行。
- 低精度、无定位和旧位置均有清晰提示。
- 在真实 Watch 户外测试采集时间、精度和耗电。
- 测试手机断连时的行为。

## Phase 3 — 语音输入与确认
目标：
- 验证 watchOS 上可用的系统语音识别与语音合成 API。
- 把录音/识别、字段解析、确认 UI、持久化解耦。
- 支持确认、取消、修改和低置信度澄清。
验收：
- 语音不可用时可通过手动路径完成同样流程。
- 原始转写保留；解析错误可修正。
- 实地测试风噪、短句、语言设置、离线行为和权限拒绝。
- 不把未经用户确认的解析结果保存为最终击球事实。

## Phase 4 — 基础球杆建议
目标：
- 支持逐杆输入 carry/total 距离。
- 在可信输入下给出简单、可解释的候选球杆与目标策略。
- 明确展示数据不足和不确定性。
验收：
- 核心决策函数有测试。
- Driver/3-wood 初始 total 数据不会被误用为 carry。
- 无可信球场几何时不编造障碍/目标区。

## Phase 5 — iPhone 管理与同步
目标：
- iPhone 查看回合、编辑球杆资料、查看击球历史。
- Watch 与 iPhone 通过经验证的机制异步同步。
- 处理重复投递、延迟、冲突和断连。
验收：
- Watch 本地保存不依赖同步。
- 同一数据多次同步不产生重复。
- 离线期间积压的数据在连接恢复后能合理处理。

## Phase 6 — 球场数据与回合回顾
目标：
- 选择球场/球洞。
- 引入合法、可信的球场几何/果岭数据。
- 显示果岭前/中/后距离和简单回合摘要。
验收：
- 记录数据源、许可和更新策略。
- 没有数据时明确提示，不伪造距离。
- 支持导出个人数据。

## 后续探索（不属于首版承诺）
- 更精细的球杆距离分布与个人失误模型；
- 天气与风向；
- CSV/手动导入第三方高尔夫数据；
- LLM 辅助解释或语音解析（需评估隐私、费用、网络依赖）；
- AR 眼镜或商业化功能。
