# M-Caddie — 测试与验收计划

## 1. 核心单元测试（`MCaddieCore`）
- Shot 创建后 ID 稳定。
- 估计落点与后续位置观察并存。
- 球位更新关联原有 Shot，而非创建第二条 Shot。
- carry 与 total 不混淆。
- 距离单位转换正确。
- 空字段/unknown 值不会导致崩溃。
- 解析置信度低时要求澄清，不会自动视为已确认。
- 决策引擎缺少球场几何或球杆数据时，返回明确的不确定性而非虚构结果。
- 风险评分/候选排序在固定输入下可重复。
- 同步重复事件的幂等处理（若放在 Core/同步模块）。

## 2. 工作流测试
场景 A：正常击球
1. 输入报告；
2. 显示待确认摘要；
3. 用户确认；
4. 保存成功；
5. 检查数据库中只有一条 Shot。

场景 B：低置信度
1. 输入不明确报告；
2. 进入澄清；
3. 用户补充；
4. 再确认；
5. 保存最终字段和原始转写。

场景 C：球位更新
1. 已有 Shot A；
2. 输入“右侧长草，球陷得比较深”；
3. 获取/模拟 GPS；
4. 追加观察；
5. 验证仍然只有 Shot A，且 A 的原始估计没有丢失。

场景 D：离线
1. 关闭 iPhone 或断开连接；
2. Watch 确认并保存 Shot；
3. 结束/重启应用；
4. 验证本地记录存在；
5. 连接恢复后验证同步不重复。

场景 E：权限和定位异常
- 定位权限拒绝；
- 定位不可用；
- GPS 精度很差；
- 定位时间过旧；
- 用户取消语音；
- 语音识别不可用或失败。

## 3. 真实设备验证
模拟器不能替代以下测试：
- Watch 户外 GPS 精度和采集延迟；
- 语音识别在风噪和高尔夫球场环境下的效果；
- Watch 屏幕关闭/应用切换时的回合体验；
- 电池消耗；
- iPhone 不在身边或断连；
- Personal Team / 开发签名导致的安装有效期与重新部署流程。
